# Upgrading OpenEMR 8.3.0 to 8.4.0

What changes between `v8_3_0` (2026-08-18) and `v8_4_0` (2026-09-13) that matters before and after an upgrade. The upgrade steps themselves are on the OpenEMR wiki; new features are in the wiki's [Release Features](https://www.open-emr.org/wiki/index.php/Release_Features).

## Before you upgrade

- No change in the PHP version, PHP extensions or Node requirement.
- **CI no longer tests:** MariaDB 10.6, MariaDB 12.2, MySQL 5.7, MySQL 8.0. If your database is one of these, check it is still supported before upgrading.
- **CI now also tests:** MariaDB 12.3.
- **Databases CI tested:** 8.3.0: MariaDB 10.6, 10.11, 11.4, 11.8, 12.2; MySQL 5.7, 8.0, 8.4, 9.3 (PHP 8.3, 8.4, 8.5, 8.6). 8.4.0: MariaDB 10.11, 11.4, 11.8, 12.3; MySQL 8.4, 9.3 (PHP 8.3, 8.4, 8.5, 8.6).

## Database

- Database version 541 → 543.
- `sql_upgrade.php` runs, from 8.3.0: `sql/8_3_0-to-8_4_0_upgrade.sql`.

Schema, as a fresh install of each creates it: 0 tables added, 0 removed, 2 changed.

- [`api_log`](../schema/api_log.md): added `client_id` varchar(80)
- [`form_care_plan`](../schema/form_care_plan.md): added `plan_engagement_category` varchar(100)

## Modules

No change.

## Pages removed

2 PHP files under `interface/` and `portal/` are gone (some were pages; some were included by pages). Bookmarks or links to them will break.

- `interface/forms/care_plan/templates/careplan_actions.php`
- `interface/forms/care_plan/templates/careplan_reason_row.php`

## Settings (Administration > Config)

**New:**

- `duplicate_patient_rescore_on_load` (Miscellaneous): Recompute Duplicate Scores On Every Report Load. Default `1`.
- `portal_onetime_max_pin_attempts` (Security): Portal One-Time Token Maximum PIN Attempts. Default `5`.

**Changed:**

- `audit_events_query`: default `1` → `0`
